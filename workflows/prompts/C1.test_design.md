Design the acceptance test cases of the feature "{{feature}}". Do not change any code in this step.

- Business requirements and acceptance criteria extracted from the BA spec: {{baScenarios}}
- Review of the built UI against the API contract (screens, UI needs, API operations and how they map): {{review}}

For every business scenario:
- map it to the screens and API operations (ids from the review) it goes through;
- write preconditions (with the provider state or fixture that sets them up), concrete test steps, test data and the expected outcomes stated by the BA;
- choose the lowest test level that proves it: component (one screen's business state), integration (UI ↔ API mapping and response handling) or e2e (a full user journey);
- cover the happy path, each named error, permission rules and validations.

Expected outcomes come from the BA only: never adapt them to what the current code does.
When a scenario cannot be tested (no screen or state for it, no API operation, no usable test data, no expected outcome, or the documents are unclear), report it under testabilityGaps instead of inventing a test.

Write {{output}} with exactly this JSON shape:
{
  "testCases": [{
    "id": string,                    // e.g. "TC-BA-ORDER-001-01"
    "requirementIds": string[],
    "title": string,
    "preconditions": [{ "description": string, "setup": string | null }],
    "steps": [{ "action": string, "uiFlowNodeId": string | null, "apiOperationId": string | null }],
    "expectedOutcomes": [{ "description": string, "kind": "ui"|"api"|"navigation"|"data" }],
    "testData": [{ "name": string, "description": string, "example": string | null }],
    "uiFlowNodeIds": string[],
    "apiOperationIds": string[],
    "level": "component"|"integration"|"e2e"
  }],
  "testabilityGaps": [{
    "requirementId": string,
    "reason": "missing_design"|"missing_api"|"missing_test_data"|"missing_expected_outcome"|"ambiguous",
    "message": string,
    "blocking": boolean
  }]
}

Use only requirement, screen and operation ids from those files. Write only that file, then stop and reply with one line.
